# Staging deployment (all doable from a phone browser)

Staging = Render free web service (branch `develop`) + Supabase free project `margin-calculator-staging`
(org "Project QA", region ap-south-1 / Mumbai).

## Already done (by Claude, via the Supabase connector)
- Schema `margin` with all Stage 1 tables, append-only triggers (`001_init`)
- Restricted role `margin_app` and its grants (`002_app_role`)
- Private storage bucket `margin-archive` (100 MB per object limit)
- `margin_app` login enabled with a generated password (given to you in chat, not stored anywhere in the repo)
- Privilege check `tests/pg/privilege_check.sql` run on staging: 9/9 tamper attempts refused

## 1. Supabase: two values to copy
1. **Database connection (restricted app role)** — supabase.com → project *margin-calculator-staging* →
   **Connect** (top bar) → **Session pooler** → copy the URI. It looks like
   `postgresql://postgres.nlubvmkdvrjgsvvxfvxm:<YOUR PASSWORD>@aws-…-ap-south-1.pooler.supabase.com:5432/postgres`
   Change it to:
   `postgresql://margin_app.nlubvmkdvrjgsvvxfvxm:<margin_app password>@<same host>:5432/postgres?sslmode=require`
   This is `DATABASE_URL`. (Use the *session* pooler: Render's free tier has no IPv6 for the direct host.)
2. **Storage key** — Project Settings → **API Keys** → *Secret keys* → create one named `render-staging`
   → copy (`sb_secret_…`). This is `SUPABASE_SERVICE_KEY`. It cannot read the `margin` tables
   (verified: `service_key_schema: false`); it is used only for the archive bucket.

## 2. Render
1. dashboard.render.com → **New** → **Blueprint** → connect GitHub → pick `jaikishanbabu/margin-calculator`,
   branch `develop`. Render reads `render.yaml`.
2. Fill the four secrets it asks for: `DATABASE_URL`, `SUPABASE_SERVICE_KEY`, `SUPERADMIN_PASSWORD`, `OPS_TOKEN`.
   (`JWT_SECRET` is generated by Render automatically.)
3. **Apply**. First build takes ~3–5 minutes. Staging URL: `https://margin-engine-staging.onrender.com`
   (Render may add a suffix if the name is taken — use whatever it shows).
4. The service refuses to start if any secret is missing or weak — check **Logs** if the deploy fails.

## 3. GitHub (repo → Settings → Secrets and variables → Actions)
- **Variables** tab → `STAGING_URL` = the Render URL (no trailing slash)
- **Secrets** tab → `STAGING_OPS_TOKEN` = the same value as Render's `OPS_TOKEN`

## 4. Acceptance run (required before Stage 1 is complete)
1. Open `<STAGING_URL>/admin/` → log in as `superadmin`.
2. **Admins** → create one admin. Log in as them in a private tab and upload one real SPAN file
   (enter its cycle) and one ELM/other file.
3. **Backups** (as superadmin) → **Run backup now**, then **Run restore test** → every check must pass.
4. GitHub → **Actions** → *Staging backup + restore test* → **Run workflow** → must be green.
5. GitHub → **Actions** → *Staging health check* → **Run workflow** → must be green.
6. **Audit log** → **Verify chain** → "Chain intact".

## Free-tier behaviour to expect
- **Render free** sleeps after ~15 min idle; the first request then takes ~30–60 s. Its disk is wiped on
  every deploy/restart — nothing is stored there (the app refuses `STORAGE_BACKEND=local` outside dev).
- **Supabase free** pauses projects with low activity over 7 days (warning email ~1 week before; restorable
  for 90 days). Daily uploads and the daily health check are *not* a guarantee against pausing. The
  health check exists to alert you, not to keep the project awake.
- **No automatic Supabase backups** on the free plan. The weekly backup workflow is the only backup;
  Stage 2 adds Google Drive as a second, independent destination. Production needs Supabase Pro.
- Storage quota: 1 GB on Supabase free. Watch archive growth (Stage 2 adds a usage readout).
